# 2단계: 점수 분류기

```text
질문 → 시그널마다 켜짐/꺼짐 → 켜진 시그널의 가중치를 더한 점수 → 경계값 이상이면 big
```

1단계 `keyword`는 완성되어 있습니다.

## 시그널과 가중치

`classifiers.py`의 `SIGNALS`를 보세요.

| 시그널 | 가중치 | 켜지는 조건 |
| :--- | :---: | :--- |
| `code` | +0.35 | 코드 블록이나 코드 관련 단어 |
| `reasoning` | +0.30 | "왜", "분석", "비교", "증명" … |
| `technical` | +0.30 | "설계", "아키텍처", "캐시" … |
| `long` | +0.15 | 200자 초과 |
| `multi_step` | +0.10 | 번호 매긴 단계, "먼저 … 다음" |
| `simple` | −0.30 | 인사·번역·뜻 묻기, 또는 15자 미만 |

키워드처럼 "처음 걸린 하나"로 정하지 않고, 여러 시그널을 **모두 더해** 판단합니다. 음수 가중치는 "쉬움" 쪽으로 끌어당깁니다.

## 실습 2-1: `difficulty` 만들기

`signals(text)`는 `{"code": True, "long": False, ...}`를 돌려줍니다. 켜진 시그널의 가중치(`SIGNALS[name][0]`)를 모두 더해 돌려주세요.

## 실습 2-2: `score` 만들기

점수가 `THRESHOLD` 이상이면 `"big"`, 아니면 `"small"`을 고르고 `(결과, f"score={s:+.2f}")`를 돌려줍니다.

```bash
uv run run.py score --no-answer
uv run run.py all --no-answer        # keyword와 비교
```

## 실습 2-3: 조절해 보기

- `THRESHOLD`를 0.1, 0.3, 0.5로 바꾸면 정확도가 어떻게 변하나요?
- 20번 "인생의 버그 같은 순간에 대한 짧은 시"는 왜 큰 모델로 가나요?
- 22번 "P와 NP가 같지 않다는 걸 보여줘"는 어려운 질문인데 왜 작은 모델로 가나요?
- 가중치나 단어 목록을 고쳐 이 둘을 맞히면, 다른 질문은 괜찮나요?

> 정리: 점수 방식은 여러 시그널을 함께 보니 키워드보다 덜 깨집니다. 그래도 여전히 단어를 셀 뿐, 질문의 뜻은 모릅니다.
