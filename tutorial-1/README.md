# 1단계: 키워드 규칙 분류기

```text
질문 → "이 단어가 있으면 이 모델" 키워드 → small / big
```

## 먼저: 도입

저장소 루트에서 `llm.py`로 같은 질문을 두 모델에 보내 봅니다.

```bash
cd ..
uv run llm.py "파이썬에서 리스트를 뒤집는 방법은?"
uv run llm.py "주문·결제·배송을 마이크로서비스로 나눌 때 데이터 일관성을 지키는 설계를 해줘"
cd tutorial-1
```

같은 질문에 두 모델이 어떻게 답하는지, 시간과 토큰이 얼마나 다른지 봅니다. 쉬운 질문에도 큰 모델이 꼭 필요할까요?

## 실습 1-1: `keyword` 만들기

`classifiers.py`의 `keyword()`를 채웁니다.

- `KEYWORD_RULES`를 위에서부터 보면서, 키워드가 질문에 들어 있으면 `(모델, f"rule={키워드}")`를 돌려줍니다.
- 하나도 안 걸리면 `(DEFAULT, "rule=없음")`을 돌려줍니다.

```bash
uv run run.py keyword --no-answer
```

## 실습 1-2: 규칙 고쳐 보기

❌ 표시된 질문을 보고 `KEYWORD_RULES`에 규칙을 더하거나 순서를 바꿔 보세요.

- 17번 "'디버깅'이라는 단어는 어디서 유래했어?"는 왜 큰 모델로 갔나요?
- 24번은 어려운 질문인데 왜 작은 모델로 갔나요? 규칙 순서를 바꾸면 해결될까요?

정답에 가까워졌다면 답변까지 받아 봅니다.

```bash
uv run run.py keyword
```

> 정리: 규칙은 빠르고 공짜고 이유가 분명합니다. 하지만 단어만 볼 뿐 뜻은 모릅니다.
